# Working brief: Adding Agents

## Reader question

How should we think about project capacity when adding an agent differs from bringing another person onto the team?

## Argument to develop

Human staffing metaphors make agent work easy to describe: give a colleague a task, add another developer, assemble a team. But they can obscure the properties that matter. A person arrives with experience and can gradually develop durable knowledge, relationships, judgment, and responsibility for the project. An agent's useful contribution depends on the model, supplied context, tools, memory, permissions, and system that coordinates its work. Several sessions do not automatically become several informed colleagues.

At the same time, agent work can be started, repeated, paused, or discarded on different terms from human staffing. Parallel exploration, independent checks, or isolated implementation tasks may become practical when assigning another person would be disproportionate. The essay should find where this changes the shape of a project, then follow the costs that remain or emerge.

Brooks provides a way to ask about task division and communication. Van den Berg's article supplies the contemporary prompt. Neither should become an automatic verdict that adding agents always helps or always slows a project down.

## Possible shape

1. Show the same project decision in two forms: bring in another person or start another agent. Ask what each participant needs before useful work begins.
2. Explain the conditions behind Brooks's argument: learning the project, communication, dependencies, and integration. Distinguish a late-project staffing decision from scaling an already planned parallel task.
3. Identify which costs change with agents: preparing context, replicating a setup, trying alternatives, maintaining shared state, and checking results. Compare the contribution with its full cost, including human attention and compute.
4. Follow one bounded task that benefits from parallel agents and one tightly coupled task that does not. Measure accepted work, elapsed time, review effort, rework, and failures rather than generated volume.
5. Return to the metaphor. What should a project owner specify when deciding whether to add a participant: another perspective, an independent check, execution capacity, decision authority, or long-term ownership?

## Questions to pursue

- Which costs of introducing a human actually disappear, and which reappear as context preparation, retrieval, tool setup, or repeated correction?
- When do separate agents provide useful independent perspectives, and when do shared models and assumptions produce correlated errors?
- Who controls a shared plan and working state? What happens when two agents change the same assumption or depend on each other's unfinished work?
- Which tasks can proceed independently, and which wait on a decision, experiment, approval, or integrated result?
- Can agents also reduce planning, review, and integration effort? What evidence would show that the supposed bottleneck has moved or shrunk?
- What does a human teammate contribute over a project's lifetime that a short-lived agent session does not carry automatically?

This is an essay brief. Its human-versus-agent comparisons are questions to test with actual work, not a fixed taxonomy or a new staffing formula.
