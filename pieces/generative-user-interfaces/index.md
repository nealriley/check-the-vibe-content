# Generative User Interfaces

## The idea

A survey of recent developments in systems that generate or adapt **their own user interface during use**. What can these systems actually decide: the words and data shown, the choice of components, their layout, or the interactions themselves? The piece should make the capabilities visible through concrete examples available at the time of writing, without treating a demo and a dependable product as equivalent.

The central design question is whether generative UI is best understood as an interface appearing from scratch or as a system **selecting and rearranging known components** within a design system. Components, design tokens, interaction patterns, and constraints may make the result more coherent and usable while still allowing the interface to fit a particular task. That is a working angle to test in the survey, not a conclusion to assume.

## What to investigate

- Distinguish content placed in a fixed UI from a system choosing components, composing a new view, or generating new interface code and behaviour.
- Compare interfaces generated at runtime for a user with tools that generate application code for a developer. Both may be relevant, but they answer different questions.
- Look at what the design system fixes in advance and what the system may change: component catalogue, layout, visual language, interaction rules, accessibility, and permissions.
- Ask how users inspect, correct, save, or return to a generated view. Consider reliability, consistency, accessibility, latency, and trust alongside visual novelty.
- Separate reported capabilities from observed behaviour. Date examples and set a research cutoff when the survey is written, since “recent” will age quickly.
