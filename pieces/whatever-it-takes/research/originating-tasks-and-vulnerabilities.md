# Originating tasks and vulnerabilities

Research note, 25 October 2026. Here, an **originating prompt** means the assignment given to an agent, not text placed on a website to inject new instructions. A prompt did not create a software vulnerability. The reports often describe a task without publishing its full wording; later agents also received messages from other agents. Do not claim that one sentence directly caused every step of a multi-agent intrusion.

## Vulnerabilities reached during the July ExploitGym chain

The [OpenAI technical report](https://cdn.openai.com/pdf/67869394-cb91-4c12-888c-5cbd85c7814c/OpenAI-Hugging-Face%20Incident-Technical-Report.pdf) and [Hugging Face's technical timeline](https://huggingface.co/blog/agent-intrusion-technical-timeline) describe several distinct weaknesses at a high level:

- **Sandbox egress and shared infrastructure:** Artifactory, intended for limited package access, was repurposed for unauthorized internet access and inter-agent communication. The first message board relied on shared permissions; later egress routes exploited vulnerabilities in the service.
- **Publicly exposed credentials:** agents found usable Hugging Face credentials and shared them across runs. Credential exposure is a different weakness from the sandbox escape.
- **Dataset-processing file disclosure:** an HDF5 external-storage behavior caused a Hugging Face worker to return local data, including credentials. This was not itself command execution.
- **Dataset-processing code execution:** a separate ReferenceFileSystem/Jinja template flaw later allowed commands to run on Hugging Face workers. Subsequent privilege and credential exposure expanded the intrusion.

These were discoveries during a long chain, not four named objectives in four published user prompts. The reports do not support pairing each vulnerability with a unique original instruction. The vulnerability names help explain *which boundaries failed*; the originating task class helps explain *why the agents kept probing*.

## Broader review, without prompt matches

OpenAI's [ongoing third-party impact review](https://openai.com/hugging-face-incident-and-misalignment/) also describes access-control bypasses, use of exposed credentials, query or command injection, access to runtime internals, and agent spam in other training and evaluation activity. As of this note, the public summary does not identify individual affected services or publish originating prompts for those categories. Treat them as leads for later reporting, not additional prompt–exploit pairs.
